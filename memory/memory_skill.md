# Memory Skill — 记忆管理可操作技能

> 提炼自 `memory_management_sop.md` (L0)。把"约束"转成可执行清单：写入前 → 分类 → 同步 → 检查。
> 适用：需要新建/修改 L1/L2/L3 条目的任何场景。

---

## 1. 写入前：Action-Verify Gate

- [ ] 信息源是**已成功的工具调用结果**（shell/file_read/代码运行通过）？
- [ ] 不是模型固有知识 / 推理猜测 / 未执行计划 / 未验证假设？
- 口号：**No Execution, No Memory.**

---

## 2. 分类决策树（3 步定位）

```
这条信息该放哪层？
├─ 环境特异性事实 (IP/非标路径/凭证/ID/API Key) → L2
│   └─ 高频 → L1 第一层 key→value；低频 → L1 第二层仅关键词
├─ 通用操作规律 (全局避坑/排查方法/不针对特定任务) → L1 [RULES] 1 句压缩
├─ 特定任务技术 (操作艰难+未来复用) → L3 SOP/脚本
└─ 通用常识 / 冗余 → 丢弃
```

---

## 3. 易变状态自检（写入前必查）

下列信息**严禁**写入 L1/L2/L3：
- 当前时间戳 / 临时 Session ID / 正在运行的 PID
- 某个具体绝对路径 / 连接的设备信息
- 会话内一次性状态

---

## 4. L1 同步规则（操作 → L1 变更）

| 操作 | L1 同步动作 |
|------|-------------|
| L2/L3 新增场景 | 默认低频 → L3 列表加文件名（自解释不加描述，反直觉才加括号触发词 2-4 字）|
| L2/L3 删除场景 | 删除对应层关键词/映射行 |
| L2/L3 修改值 | 不影响定位则不动 L1 |
| 发现通用避坑规律 | 压缩为 1 句加入 [RULES] |

---

## 5. L1 编辑红线（最关键技巧）

- **必须 patch，不允许 overwrite / code run**（改不动宁愿不改）
- ≤ 30 行硬约束，< 1k tokens 期望
- 禁止：密码、API Key、How-to、特定任务技术细节、日志记录

---

## 6. 命名自解释规则

| ❌ 反例 | ✅ 正例 |
|---------|---------|
| `sop_name(场景A:方法1+方法2+方法3)` | `sop_name(场景A)` |
| `discord_slate_sop(Slate输入框)` (名字已自解释) | `discord_slate_sop` |
| 括号内写机制/方法/步骤 | 仅写反直觉场景触发词 2-4 字 |

---

## 7. 重构期 Sanctity 保护

- 行动验证过的有效配置、避坑指南、关键路径 → **严禁丢弃**
- 可压缩文字 / 可迁移层级（L2↔L3），但不能丢准确性与可追溯性
